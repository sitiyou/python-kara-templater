# E01–E12 实施案例卡

本文件固定首轮实现的可检查目标，先于新示例输出建立。历史调研链接见[计划](ass-animation-engine-plan.md)。自有文本、几何和动画用来验证机制，不复制外部模板或素材。实现与已有渲染证据见下方核对表；有输出不等于全部质量条件已经验收。

当前十二例的接口、明确预期与逐例验收索引见[全案例核对](case-interface-audit.md)，最新默认预算编译成本见[机器可读快照](case-interface-audit.json)。下方按批次保留的旧成本和“待验收”文字属于历史记录。

## 公共实验配置与预算

- 画布 1280×720，时间单位秒，ASS 时间量化到 10 ms；采样默认 50 Hz，以免事件时间网格产生不规则长度。
- 单例 6 秒：0–1 秒入场、1–4 秒演唱、4–5 秒收尾、5–6 秒留空。特殊时序在案例中另行声明。
- 字体使用仓库 tests/fonts/DejaVuSans.ttf 和 KaraTestCJK.ttf；许可随 tests/fonts 保存。实际可用 CJK 字符由字体 cmap 检查，不以宿主字体恰好存在为前提。复杂回退单独测试。
- 每例导出上限：25,000 事件、10 MiB UTF-8、峰值 1,000 活动事件、每个路径 4,096 控制点。展开前按保守上界预检，生成中再检查。超限失败，不自动减帧或减少花瓣。
- 整曲夹具：同一组案例重复并平移至 180 秒，最多 250,000 事件、100 MiB、峰值 2,000 活动事件。先固定资源预算，渲染耗时测量报告，不凭未测量的机器速度承诺实时播放。
- 平面参考允许 1 像素几何误差；颜色插值通道误差目标不超过 2/255（栅格抗锯齿边缘另报）；时间量化不超过 10 ms。自定义函数只报告采样间隔，不虚构严格误差上界。
- 关键帧：0、0.5、1、1.5、2.5、3.99、4、4.5、5 秒，加每个离散边界前后 10 ms。黑、白、棋盘与自制彩色渐变背景；直接渲染导出的 ASS，并记录 renderer/font/seed。
- 单例生成与渲染耗时、峰值活动事件、总字节数写入机器可读报告。连续与乱序取帧必须一致；固定种子重复生成必须字节一致。

## 逐例目标

### 固定资产清单

机器可读清单为 [engine-assets-validation.json](engine-assets-validation.json)，用 `uv run python -m tools.validate_engine_assets docs/engine-assets-validation.json` 重建。它记录当前字体字节/哈希/内部 family/style、Unicode cmap 覆盖、随附许可路径与哈希，以及 CASES 中 E01–E12 作者源码的哈希；同时检查六份字体和许可在 MANIFEST.in 中的显式包含。源码哈希用于标明资产/动画定义快照，不代表旧视觉报告自动适用于任意后续改动。

| 文件（均位于 tests/fonts） | 用途与来源 | 随附许可 |
| --- | --- | --- |
| DejaVuSans.ttf | 核心案例拉丁正文、注音及测量；内部 family 为 DejaVu Sans，style 为 Book | LICENSE（字体目录内，含 Bitstream/DejaVu/Arev 说明） |
| DejaVuSans-Oblique.ttf | 倾斜字形的边界/墨迹回归，仅用于额外回归用例 | 同上 |
| KaraTestPrimary.ttf | DejaVu Sans 的改名字体子集，只保留 A 和空格，强制触发可控回退 | 同上；重建脚本 tools/build_test_font.py |
| KaraTestCJK.ttf | Sarasa UI SC 改名子集，仅 U+6642 時 与 U+3005 々；E01/E03 及双语扩展示例 | LICENSE-Sarasa（SIL OFL 1.1 与原版权说明） |
| KaraTestHangul.ttf | Sarasa UI SC 改名子集；12 个码点，用于预组韩文与 jamo 塑形回归 | LICENSE-Sarasa |
| KaraTestMultiscript.ttf | Sarasa UI SC 改名子集；今天、かな、한글，共 6 个码点，避免发行测试依赖宿主 CJK 字体 | LICENSE-Sarasa |

三个 Sarasa 子集的重建入口为 `tools/build_hangul_test_font.py FONT_TTC LICENSE`，要求源字体的第 7 个 face 名称为 Sarasa UI SC，复制输入许可并改名；仓库随附的是已生成夹具。源 TTC 本身不是运行示例所需资产，重新生成也不能假定任意版本源字体会得到相同哈希。fontTools 是夹具生成/资产审计的检查依赖，不是 ASS 播放依赖。

E01–E12 的短歌词、几何和时间表直接写在清单列出的 examples 源文件中，按项目根 LICENSE 随源码分发。E04 花瓣为作者定义的矢量路径，E05 网格由字形路径切分，E08 明确提供有序折线/贝塞尔笔画，E10 使用圆环/方形与固定字体字形；没有待下载的第三方图片、花瓣贴图、手写笔顺或视频。外部模板只作为机制参考，出处见计划的逐例链接；不将原模板或用户参考截图复制进分发资产。

生成验证会注册随附字体，播放验证以 fontsdir 提供相同文件；仅有相同 family 名称不能保证用户播放器选择同一字节。独立使用输出 ASS 时应向播放器提供这些字体。固定黑/白/棋盘/彩色渐变背景由验证工具生成，无外部视频依赖；核心四背景报告与 E08 边界修复后的覆盖报告分别保存实际 renderer、字体与取帧时钟，不混用历史快照推断最终视觉达标。

## 限制与尚待提供的证据

上述预期是人工明确的验收目标，不是独立制作的可播放参考。实际字体清单、libass 版本、输出和成本已随各例报告保存；机器/平台差异、全部背景与误差条件仍需逐项核验。旧 v0.1.0 的模板/代码/修饰符/helper 回归另有[兼容矩阵](legacy-templates.md)，不由新案例替代。

不支持播放端 shader、自定义混合模式、真实 3D 或任意视频纹理。普通标准 ASS 标签不保证所有播放器逐像素一致。原生、采样和昂贵近似必须在编译报告中区分，不能仅凭文件可解析宣布视觉达标。
