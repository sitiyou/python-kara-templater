## 定位与目标

本库为已有歌词动画添加特效。歌词内容、排版、显示窗口、演唱时间和扫色进度已经存在，作者在这些内容上选择目标、添加外观和组合效果。

作者体验采用类似 Textual 的声明式组件方向：声明结构与样式，通过对象或选择器绑定领域行为。结构、外观和行为各有明确位置，普通效果使用领域默认值，特殊需求再展开配置。这取代此前以 Manim 为参照、逐条添加动画并显式绑定时间的特效定义方向；对象与渲染分离、效果可组合、属性统一求值仍作为内部架构原则。

不引入 `Scene / construct / play`、全局播放游标或重新编排整段动画的工作流。也不要求依赖 Textual；CSS 文本语言、完整浏览器 CSS、响应式状态、实时事件循环和通用 UI 组件系统不属于本次范围；使用 Python 声明样式规则，并实现下文明确限定的选择器优先级与覆盖机制。

本计划接续 [原实施计划](karaoke-effects-plan.md)。原计划中的时间、几何、来源追踪与输出精度契约继续适用；特效定义方向以本文为准。原有完成记录不代表本次特效系统已经完成。

首个验收案例是 [layered_glow.py](../examples/layered_glow.py)。目标不是为它增加专用快捷函数，而是让同等复杂度的效果都可以直接组合。

## 重构前的问题

`KaraokeEffect` 可以配置预设效果，但超出预设后，作者必须修改 `EffectPlan.layers`。当前示例因此需要按 `animation_id` 去重、清除裁剪和有效窗口、拼接内部 ID、重建图层，以及从 `origin.sources` 反查时间。

这些操作发生在扫色已经拆分输出之后。作者为了给完整对象加辉光，又要从输出碎片恢复对象及其时间关系。缺失的是编译前的特效组合层，不能只靠参数缩写解决。

## 预期作者体验

仅隐藏输出细节仍不够：反复调用通用 `add()` 并为每个效果填写 `during=...`，依然像编排执行脚本。默认入口应直接表达组件结构及歌词领域行为。

以下为已实现的特效定义方式，完整导入与运行入口见 examples/layered_glow.py。`compose()` 声明组件结构和初始外观；`configure()` 在组件与既有歌词来源绑定后，通过对象及选择器配置样式和行为。先按来源范围完成样式解析，再进行受字号等属性影响的布局、字形能力校验和动画目标解析；不能先固定布局再修改影响测量的样式。每行建立独立实例，配置完成后编译为确定性的输出计划。

```python
class LayeredGlow(Effect):
    def compose(self):
        yield Lyrics(
            Body(fill=WHITE, stroke=BLACK, stroke_width=5),
            Ruby(stroke_width=3, offset_y=10, follow="syllable"),
            Halo(id="base", color="#9e6d64", opacity=0.8,
                 blur=10, width=10, ruby_width=6),
            Halo(id="sung", color="#67e5ff", opacity=0.2,
                 blur=10, width=10, ruby_width=6),
        )

    def configure(self):
        guide = self.source.style == "LEAD"
        self.text.sweep(
            fill="#01829d", stroke=WHITE,
            curve="linear" if guide else ProgressCurve.two_stage(time_fraction=3 / 17, progress_fraction=0.3),
            padding=24, lead=24, tail=24,
        )
        self.query_one("#sung").on_singing(opacity=(0.2, 0.8), keep=True)
        self.text.fade(in_ms=800, out_ms=200)
        if guide:
            self.ruby.hide()
        else:
            self.syllables.on_singing(pulse=1.1)
```

上述示例显式配置正文白字黑边，ruby 继承其颜色；未指定正文外观时继承来源 ASS 样式。扫色只覆盖指定颜色，保留各自描边宽度。`self.text` 表示正文与 ruby，`self.syllables` 表示既有歌词单元的整体强调目标。`Halo` 声明会绑定到对应正文与 ruby 目标，无需用户重复创建每个音节的辉光；默认覆盖完整目标、随目标变换，辉光按声明顺序由后向前叠放，正文在辉光之上。隐藏 ruby 同时隐藏其关联装饰。

`sweep()` 默认使用实际演唱进度；`on_singing()` 的属性变化默认使用目标演唱包络，`keep=True` 表示结束后保持终值，开始前保留初值；pulse 结束后恢复原缩放。`fade()` 默认使用显示窗口并作用于关联装饰。正文辉光使用所属单元的包络，ruby 辉光使用对应 segment 的包络。显式时间、轨道、曲线和跟随配置作为进阶能力保留。

`on_singing()` 声明时间规则，不注册依赖实时播放的回调。使用普通 Python 分支表达 LEAD 等差异，在添加行为前选择配置，避免先添加 pulse 再调用 `clear_pulse()` 撤销。

## 架构边界

数据流：已有歌词与布局 + 声明组件结构 → 组件绑定与目标选择 → 领域行为及默认时间解析 → 属性和几何合成 → 输出计划 → ASS 编译。

| 层次 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| 来源与布局 | 原始行、单元、segment、字形簇、ruby、位置与时间 | 从输出片段重建作者对象 |
| 组件与创作目标 | 声明结构、初始样式、稳定身份、选择、分组及关联关系 | 暴露 ASS 裁剪碎片或建立通用 UI 系统 |
| 领域行为 | 扫色、强调、淡入淡出、属性变化、默认时间解析及冲突检查 | 要求普通效果反复手工绑定时间 |
| 求值与展开 | 解析时间、传播变换、合成属性、生成输出计划 | 改写原始演唱时间来适应装饰 |
| ASS 后端 | 裁剪、分层、原生变换、必要采样、预算与诊断 | 决定作者应如何组织效果 |

优先复用 `model.py`、`layout.py`、`characters.py`、`timeline.py`、`animation.py` 的已有能力。`recipe.py` 中混合的目标构造、预设逻辑和输出展开需要拆分；`EffectPlan`、`TextLayer`、`sampling.py`、`ass_output.py` 保留适用的后端能力。最终模块划分以实现中的职责为依据，不为旧结构增加重复模型。

## 核心契约

### 目标与选择

首版提供组件类型、局部 `#id` 和类标记选择，以及正文、ruby、音节的便捷访问。ID 在每行效果实例内唯一；`query_one()` 对零个或多个匹配均报告清晰错误，集合查询允许空结果并保留来源顺序。不同歌词行之间不共享可变组件状态。选择器查询编译前组件及来源目标，不查询输出图层；暂不实现完整 CSS 选择器语法。

组件初始样式与行为规则分开保存。配置阶段明确指定的样式可覆盖默认值，行为不因后一次方法调用而静默消失；同属性重叠行为仍遵循下述冲突契约。组件继承及默认值在 P0 明确，不能依赖任意调用顺序猜测意图。

作者操作行、歌词单元、演唱 segment、可独立绘制字形簇、ruby 和装饰。必须区分歌词单元与演唱 segment：一个单元可以含多个读音和时间段，不能假定“一字一音节”。选择器应复用原始来源地址和已有布局映射。

已实现的来源集合入口：`self.syllables`、`self.characters`、`self.segments`，以及 `self.syllables[i].characters` / `.segments`。集合支持迭代、索引和切片；`text` 读取正文，`source_refs` 返回现有 SourceRef，`intervals` 保留原始演唱区间，segment 集合的 `readings` 返回各段读音。segment 集合的正文按所属单元去重，读音与区间则逐段保留。字符地址仍由所属单元的 SourceRef 加 TextRange 表达。

对 segment 集合配置行为时，每段使用独立时钟，驱动其所属单元的正文，缩放采用单元共同中心；开启 ruby 跟随时只传播到对应来源读音及其装饰。需要跨停顿的连续包络时选择 syllable。静态单元没有 segment；空正文单元仍保留来源单元和时间段，但没有字符候选；零时长 segment 不从来源集合中删除。不能在布局前把 segment 当成一组字符，因此 `.segments.characters` 和 `.characters.segments` 明确报错。

```python
for syllable in self.syllables:
    if len(syllable.segments) > 1:
        syllable.segments[1].on_singing(pulse=1.15)
```

独立 ruby 行为入口为 `self.rubies`，也可以通过 `self.syllables[i].rubies` 或 `self.segments[i].rubies` 选择。它只包含有读音文本的来源段，`text` 返回读音文本；`source_refs` 和 `intervals` 仍指向原 segment。`.segments` 可返回对应演唱段集合。`self.ruby` 保留为声明组件，用于整体样式、隐藏和跟随配置。

```python
self.rubies[0].on_singing(pulse=1.1)
self.rubies[1].on_singing(offset_y=lambda p: -8 * p)
```

独立 ruby 动画使用自己的中心与对应 segment 时钟，不作用于正文；其装饰按 Follow 配置继承变换。Ruby 的 follow 开关只过滤从正文传来的行为，不禁用 ruby 自己的行为。自身行为与跟随行为仍须通过同一属性冲突与合成校验；不同中心的重叠缩放不能隐式相乘。隐藏 ruby 连带抑制其装饰与属性函数求值。

来源集合的 `.style` 和 `.add_class()` 已接入样式层。例如：

```python
self.syllables[0].add_class("accent")
self.characters[1].style.sung.fill = RED
self.rubies[0].style.sung.fill = BLUE
```

正文单元与字符样式映射到既有正文范围，同一范围共用声明，不引入另一套样式层级。重叠范围仍按已有范围层叠规则合成：显式声明优先于类规则，不因为范围更窄就自动获得更高优先级。ruby 样式按来源单元/segment 地址保存，只影响该读音。目标层继承组件已解析的外观，仅追加目标新增匹配规则与显式声明；不会重新用通用规则覆盖组件显式颜色。

集合属性赋值广播到各目标，读取返回共同的显式声明；声明不一致时报错，空集合返回 UNSET，赋值仍校验参数。INHERIT 读取组件对应状态的外观，UNSET 移除目标覆盖。segment 是时间目标，不能直接设置静态外观，应选择所属正文或 `.rubies`。逐目标字号仍受混合字体布局能力限制，不能静默偏离测量结果。

来源集合已支持 `.query(selector)` / `.query_one(selector)`，返回同类来源集合，可继续调用样式及行为接口。`Effect.query()` 继续查询声明组件，避免 `ruby` 同时指组件和具体读音。两者共用有限选择器解析器；来源查询支持 `syllable`、`character`、`segment`、`ruby` 类型，代码类标记、属性等值、局部 ID 与后代关系。

```python
self.characters.query('[text="星"]').add_class("red")
self.segments.query_one('[unit=0][segment=1]').on_singing(pulse=1.15)
self.rubies.query('syllable.lead segment[segment=1] ruby').style.sung.fill = BLUE
```

来源层级为正文组件 → syllable → character，或 syllable → segment → ruby。属性包括 `style`、`unit`、`text`；字符的 `start/end` 为单元内码点范围，segment/ruby 提供 `segment`、`start_ms/end_ms`，segment 另有 `reading`。局部 ID 为 `unit-{ui}`、`char-{ui}-{start}-{end}`、`segment-{ui}-{si}`、`ruby-{ui}-{si}`，只在来源结构不变时稳定；普通代码优先使用属性查询或集合索引。

查询不创建样式范围，不依赖输出拆分；在当前集合顺序中筛选，重复文本保留全部匹配，空结果允许继续配置，query_one 对零个或多个匹配报错。查询没有运行时唱后状态，`:sung` 仅用于样式解析。来源类型用于集合查询；StyleSheet 继续匹配视觉组件与正文/ruby 样式节点，可用查询给目标添加类后应用类规则，不把时间段本身当成独立绘制对象。

目标身份在一次构建与编译过程中稳定；不会因扫色分区、采样或视觉层展开而改变。不承诺源数据编辑后的永久 ID。分组只建立效果作用关系，不复制或修改来源歌词。

### 装饰与跟随

辉光是依附目标的独立视觉对象，可添加多层并独立设置颜色、宽度、模糊和透明度。正文扫色不应默认裁剪整对象辉光；需要随扫色裁剪的装饰必须显式表达。

位置、缩放、透明度、显示窗口分别定义跟随规则。组缩放使用共同中心；逐字缩放使用各自中心。ruby 跟随正文的时间与变换不意味着复制正文的字号或描边。必须避免父组与子目标重复应用变换。

### 时间绑定

默认绑定既有显示窗口、演唱区间或主体扫色到达时间，允许显式偏移、持续时间和曲线。内部继续使用绝对整数毫秒，输出阶段才转换为 ASS 相对时间。

多 segment 目标应区分“首段开始至末段结束的连续包络”和“按实际演唱进度变化”：前者可跨停顿继续变化，后者在停顿时保持进度。重复演唱和并行轨道需要明确轨道选择或聚合策略，不能靠时间重合猜测归属。

无时间目标保持初始属性；零时长变化按明确的瞬时切换规则处理。效果超出显示窗口时裁掉输出，不改变原动画进度。辉光边缘外扩及预扫不能改变主体演唱时钟。

### 颜色输入与内置值

提供可从包顶层导入的常用颜色常量：`WHITE`、`BLACK`、`RED`、`GREEN`、`BLUE`、`YELLOW`、`CYAN`、`MAGENTA`、`ORANGE`、`PURPLE`、`PINK`、`GRAY`。常量统一使用已有 `Color` 类型，各颜色的准确 RGB 值需在实现和文档中固定，不随主题或环境变化。

特效系统所有颜色参数统一接受 `Color` 或 `"#RRGGBB"` 字符串，在输入边界转换并验证；保留 `Color.hex()`，方便命名和复用自定义配色。透明度继续作为独立属性，例如 `Halo(color=CYAN, opacity=0.2)`，不混入颜色常量。

示例中白色、黑色可直接使用内置值；`layered_glow` 的 `#01829d`、`#9e6d64`、`#67e5ff` 等特殊配色保留准确色值，可定义为局部命名常量，不用近似内置颜色替换。

### 代码层样式表与分色

颜色定制只在 Python 代码层进行，不增加 ASS 私有色盘 section、行内色盘引用标签或角色协议，也不把导入 ASS 行内颜色标签作为本次任务。ASS 原始行样式仍可作为基础外观；现有导入器对不支持的 override 继续明确报错。

输入既可以是 `Document.parse()` / `Document.load()` 得到的文档，也可以是直接构造的 `Document`。后者不等同于显式 `KaraokeItem` 输入：包含普通 karaoke `Line` 时，两种 Document 都经过同一来源归一化入口；显式 items 是另一个受支持入口。归一化之后，全部使用同一套目标选择、样式解析和效果编译。

当前解析 ASS 不提供为特定歌词附加 class、角色或色盘的字段。不能要求作者为了分色修改 ASS、拆分 Dialogue、创建特殊 ASS Style 或填写 Actor/Effect 等约定字段。代码可以根据已有来源的文本、时间、顺序选择某行，再选择该行正文范围、添加类标记或直接覆盖样式。ASS 样式名只是一种可选的已有信息筛选条件，不是行内分色的前提；重复文本不能默认被当成唯一身份。

使用 `StyleSheet(rule(...), ...)` 描述规则，支持组件类型、ID、代码添加的类、有限属性筛选、后代关系和 `:sung` 状态。`body:sung` 表示唱后配色，并不表示整个对象瞬时换色；扫色仍根据空间覆盖混合唱前与唱后区域。基础规则同时为两种状态提供默认值，状态规则只覆盖差异。`sweep()` 默认读取解析后的样式；显式传入填色等便捷参数应转换为对应的样式覆盖，不另建一套配色路径。

`self.text.sweep(fill=RED)` 等价于为正文和已声明的 ruby 写入 `.style.sung.fill = RED`，同时配置扫色行为。随后直接修改同一属性会替换该声明，设为 `UNSET` 会移除该覆盖，重新使用样式表或继承值；`sweep(fill=UNSET)` 同样可清除已有覆盖。未传颜色的 `sweep()` 不写样式。这里的赋值顺序只决定静态样式声明，不影响动画冲突规则，也不会撤销扫色行为。

覆盖顺序：来源 ASS 样式基础值 → 样式表 → 组件构造参数及 `.style` 显式覆盖。样式表按 `(ID 数, 类/属性/状态数, 类型数)` 字典序比较优先级；同级后声明者覆盖先声明者。仅覆盖实际填写的属性，不重置其他属性。`INHERIT` 显式继承对应来源，`UNSET` 移除该级覆盖并重新解析较低优先级，`None` 不承担多重含义；首版不提供 `!important`。

行内文字范围按该行纯正文 Unicode 码点编号，左闭右开，不包含 ruby 或 ASS 标签。范围可跨来源单元，但不改变单元、segment 或演唱时间。来源阶段先记录范围与类标记，布局后检查是否切开不可独立绘制字形簇，不能靠改变文字整形来满足分色。

ruby 默认继承对应正文前后颜色，自身规则可覆盖；来源配色无法唯一对应时要求明确配置并给出诊断。辉光颜色独立，显式设置 Halo(color=INHERIT) 或对应状态的 fill=INHERIT 时，继承所附正文/读音的已解析状态填色；UNSET 恢复独立默认色。样式层叠只解析静态及唱前/唱后外观，动画在样式解析后求值；多个动画写同一属性仍遵循动画冲突契约，不能由样式声明顺序消除。

Halo 的 `:sung` 与 `.style.sung` 已接通颜色及透明度，使用既有扫色覆盖解析空间状态。`clip="none"` 保持两侧可见；状态外观不同时通过共享遮罩区分两侧，相同时保留整目标无裁剪输出。`clip="sung"` 仍隐藏唱前区域。自身透明度动画在活动期间覆盖状态值，结束后按 keep 语义恢复各自状态或保持终值；没有配置 sweep 时不凭演唱时间自动切换状态。颜色接缝继续遵守 ASS 硬裁剪诊断。

### 必须验收的示例：一行三色交替

以下分色接口已实现，完整可运行示例见 `examples/alternating_colors.py`。歌词为 `星月风星月风`，唱前统一白色，唱后逐字循环为红、绿、蓝、红、绿、蓝。全部颜色规则和范围标记来自代码，输入没有任何分色字段。

```python
class AlternatingColors(Effect):
    styles = StyleSheet(
        rule("body", fill=WHITE, stroke=BLACK, stroke_width=3),
        rule(".red:sung", fill=RED),
        rule(".green:sung", fill=GREEN),
        rule(".blue:sung", fill=BLUE),
    )

    def compose(self):
        yield Lyrics(Body())

    def configure(self):
        # 使用已有文本筛选行，无需在 ASS 中填写分色字段。
        if self.syllables.text == "星月风星月风":
            for index in range(len(self.syllables.text)):
                role = ("red", "green", "blue")[index % 3]
                self.body.text_range(index, index + 1).add_class(role)
        self.text.sweep()
```

另用直接覆盖写法实现同一配色，验证两种写法产生相同解析结果：

```python
for index in range(6):
    self.body.text_range(index, index + 1).style.sung.fill = (
        RED, GREEN, BLUE
    )[index % 3]
```

### 效果与属性合成

扫色、缩放强调、淡入淡出和属性变化共享目标与时间绑定机制，但保留各自的领域语义。扫色是空间覆盖变化，不能简单降级为整个目标的颜色插值。

不同属性可独立组合。同一目标同一属性在重叠时间被多次写入时，默认报告冲突；覆盖、相乘或叠加等合成方式须显式声明并限制在有定义的属性上。组透明度与装饰自身透明度分别求值后相乘。顺序、继承和冲突结果应可预测，不依赖遍历输出层的偶然次序。

普通线性及分段属性变化不要求用户编写采样回调。后端能准确表达时优先使用原生 ASS 变换；不能表达的函数使用已有预算机制采样，并说明精度限制。简单自定义函数直接接收归一化时间；需要目标及时间上下文时通过显式进阶入口提供，不要求匹配输出 ID。

### 属性动画：内置曲线、函数与关键帧

常用效果使用内置曲线，自定义变化直接传函数，精确的多段编排才使用关键帧。三种表达进入同一个属性动画模型；`pulse=1.1` 等快捷配置由该模型实现，不形成独立引擎，也不限制定制能力。

以下接口已实现；各代码块是独立的配置示例，不应同时作用于同一目标区间：

```python
# 从 1.0 放大到 1.2。
self.syllables.on_singing(
    scale=Transition(1.0, 1.2, rate=smooth),
)

# 放大后缩回；默认对称往返。
self.syllables.on_singing(
    scale=Transition(1.0, 1.2, rate=there_and_back),
)

# 前 20% 放大，保持至 65%，最后 35% 缩回。
self.syllables.on_singing(
    scale=Transition(1.0, 1.2, rate=there_and_back(
        peak_at=0.20, return_at=0.65,
        rise=ease_out, fall=ease_in,
    )),
)

# p 为当前绑定区间的归一化时间，函数返回实际倍率。
self.syllables.on_singing(scale=lambda p: 1 + 0.2 * sin(pi * p))

# 显式指定每个音节的动画区间，单位为毫秒。
self.syllables.animate(
    scale=Transition(1.0, 1.2, rate=there_and_back),
    during=(singing.start - 100, singing.start + 300),
)
```

`Transition(a, b, rate=f)` 中 `f(p)` 返回插值进度；标量属性按 `a + (b - a) * f(p)` 求值。直接传给 `scale` 等属性的函数返回实际属性值。两种函数不混用语义。归一化时间 `p` 属于每个目标解析后的绑定区间，范围为 0～1，不是整行或整个文档的全局进度。默认演唱包络跨停顿连续推进；绑定实际演唱进度时才随停顿保持。

内置提供线性、平滑、缓入、缓出、缓入缓出、往返等曲线。往返曲线可配置到达峰值、开始返回的比例及两段缓动，验证 `0 < peak_at <= return_at < 1`。普通函数与内置曲线都可用于插值进度；允许曲线超调，但最终结果必须符合属性取值约束，不静默截断。函数应只依赖输入和显式上下文，不依赖调用次数或实时状态，以保证编译与重复求值一致。

关键帧作为可选进阶表达，支持演唱起止偏移、区间比例、分段曲线及保持段。固定毫秒造成短音节关键帧倒序时报告目标与冲突时间，不自动排序；可通过比例时间规避，压缩策略如提供则必须显式选择。所有表达共享窗口裁剪、零时长、冲突检查、来源诊断和区间外行为：默认在区间外保留基础属性，`keep=True` 在结束后保持实际终值（`f(1)`），pulse 预设以原倍率作为终值。

基础字号属于布局输入，在布局前确定；动画缩放作用于已排版目标，不重新排版。整音节缩放围绕共同中心，逐字缩放围绕各自中心；中心可配置。正文、ruby、辉光和扫色裁剪使用一致的变换关系，关联装饰默认跟随且不重复缩放，允许显式关闭 ruby 的缩放跟随。

## 实施顺序与完成标准

按 P0 → P1 → P2 → P3 → P4 → P5 推进。P0 的三个用例用于约束接口设计；P3 完成一个最小纵向链路后即可试迁移 layered glow，尽早暴露抽象缺口，再完成其余组合。

本次完成意味着：作者能够通过声明组件、设置外观和绑定领域行为，为已有歌词组合普通高级特效，无需理解输出拆分或为常用行为手动安排时间；layered glow 的完整行为得到验证；其他效果也能复用同一机制；原有时间、排版、来源和输出能力没有被未经说明地削弱。仅缩短一个示例或添加专用 preset 不算完成。
