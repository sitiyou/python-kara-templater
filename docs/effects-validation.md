# 特效验证与成本基线

本记录覆盖固定字体下的静态布局、多轨合成、主体扫色与装饰范围分离，以及合成歌词的输出成本。完整测试数据见 [effects-validation-baseline.json](effects-validation-baseline.json)。动态 blur 的新增验证见下文；复杂脚本文字、任意时间函数与所有字体组合仍未全面覆盖。

## 固定条件

交叉裁剪时钟的无缝对照可运行 `python -m tools.validate_clip_seams /tmp/kara-clip-seams`，
分别添加 `--scale`、`--scale --fade` 验证动画组合。三组各 202 帧全部与未分区字形零差异，
合计 303 项检查。修复保留位置/缩放/描边/blur 的原动画时钟及透明度的原淡入淡出时钟，
仅裁剪独立细分；详见 `clip_clock_final_validation`。旧的 `scaled_clip_clock_probe` 是修复前失败记录。

并行区域和重叠策略可运行 `python -m tools.validate_parallel_paints /tmp/kara-parallel-paints`。
`parallel_paint_validation` 对照手写静态 ASS 的矩形、颜色、透明度和层序：80 帧、47 项
检查通过，四种策略各时刻与独立参考逐像素一致。底色和 union/layer 高亮均为半透明，
能发现重复底色和重复加亮；不连续区域之间保持未唱，priority 覆盖退出后恢复下层。
这是纯填色组合验证，不代替不同装饰交界的接缝验收。

加入 `--decorated` 可运行描边/辉光版，记录为 `parallel_decoration_validation`：
100 帧、57 项检查通过。包含共用同一主体时间/位置映射、分别使用 blur 6 和 24 的同步轨道，
以及不连续区域、union、priority 退出和半透明 layer。所有画面与显式静态硬裁剪参考零差异。
这证明受测整数前沿的分区输出正确，不承诺不同辉光之间平滑换色，也不覆盖所有非整数边缘组合。

三种缩放模式的位置对照可运行 `python -m tools.validate_pulse_geometry /tmp/kara-pulse-geometry`。
`pulse_geometry_validation` 使用不等宽的同音节 `W i`，逐字/同步逐字/整音节模式分别
与独立计算位置的静态 ASS 参考比较：156 帧、78 项检查全部零差异。各字独立缩放时
中心距离保持 76.5 px，整音节峰值 1.4 倍时变为 107.1 px；第二个字按前沿在约
1780 ms 触发。记录包含 10 ms 量化后的各字中心、缩放值和距离，以及渲染器版本。

相邻音节的装饰过渡对照可运行 `python -m tools.validate_adjacent_units /tmp/kara-adjacent-units`。
`adjacent_unit_validation` 记录红色 blur 30 与蓝色 blur 12 的相邻音节：预扫 200 ms、
收尾 300 ms，演唱间隙 100 ms。120 帧、44 项检查通过，联合输出与独立音节参考一致，
显示窗口截断不改变窗口内画面；分别关闭预扫/收尾均改变间隙中的画面。
独立参考共享单音节编译器，仅用于验证跨音节组合。不同颜色辉光的空间换色接缝仍单独验收。

独立辉光策略对照可运行 `python -m tools.validate_glow_strategies /tmp/kara-glow-strategies`。
新增 `glow_strategy_validation` 记录固定正文场景下的整段增强、硬裁剪和完成释放：
81 帧、32 项检查通过，动态增强与对应的静态透明度参考逐像素一致；未扫区域验证
局部辉光不会提前进入，整段辉光则已可见。比较包含 40 ms 网格之间的保持值。
完成时硬裁剪和释放画面可以相同，另检查 ASS 标签确认后者确实移除裁剪。
正文 28 个事件，硬裁剪/释放各 42，整段增强 210；该例不覆盖 ruby 或不同颜色辉光接缝。


- 字体：仓库 `tests/fonts/DejaVuSans.ttf`，SHA-256 `6038a160b491e121c1f12c7bccb4a9c8730296e3adc1086a059404ed84b7451c`；许可文本随字体提供。

- 输出：640×480，以及相同字号的 960×540 对照；画面脚本把同一字体交给 ffmpeg 的 fontsdir。

## 画面检查

初始基线在 1250、1500、1800、2200 ms 采样八种变体，共 32 帧。

| 检查 | 结果与判据 |
| --- | --- |
| 单轨与相同轨道 union | 每个采样时刻逐像素相等；重复覆盖没有重复加亮 |
| priority 轨道退出 | 1800、2200 ms 与单独低优先级轨道逐像素相等 |
| 独立透明图层叠加 | 两次 0.5 不透明度的高亮强于一次，证明叠加未被误合并 |
| blur 3 与 blur 30 | 主体实心唱前/唱后填色像素在全部采样时刻与无 blur 对照相等；允许阈值为每通道 3，本次实际为 0 |
| 分辨率变化 | 同字号、相同时间的文字区域做位置平移后逐像素相等 |
| 静态拆分与整段文字 | 231 个像素存在差异，最大通道差 30；本固定样例允许至多 500 像素、最大通道差 32 |

主体颜色检查从半唱状态的固定参考帧选取两种实心颜色，后续不重新选色。唱完后重新选择“第二常见色”会误选抗锯齿边缘；辉光可以合理改变这些边缘像素，不能把它误判成主体时间进度变化。

静态拆分差异来自独立字形定位与子像素取整。当前阈值只针对该字体、字号、样例及环境；不作为任意文字的通用容差。大 blur 的内部扫色边界采用硬裁剪，拼图中可见该边界；没有将其描述为软化扫光。

### 动态 blur 与切片取整回归

当前 `validate_effects` 扩展为十种变体、九个时刻，共 90 帧：990、1000、1200、1250、1500、1800、2000、2200、2400 ms。新增的动态 blur 在 3 与 30 之间切换，采样步长 40 ms；同时检查无属性变化的采样输出与普通输出完全相等。

新增时刻暴露并修复了两个问题：

- 每个字符的装饰边界会与扫色前沿相交，分割出不同的事件时间；随后 10 ms 取整造成原本相同的主体曲线发生偏移。现在每个字符的 mask domain 覆盖完整主体和所有所选轨道的路径，装饰范围不再切开主扫。
- 将原始裁剪曲线切成采样事件后重新取整端点，会改变整数裁剪的插值轨迹。没有缩放动画的裁剪现在保留原始端点，用相对事件起点的 `\t` 时间表示原始曲线；负起始时间已经由本地 libass 源码与实际画面验证。

修复前，大 blur 在 1200 ms 有 19 个主体像素超过原有容差，最大通道差 189。修复后，九个时刻的小、大、动态 blur 主体色差均为 0，未放宽阈值。无变化采样与普通输出逐像素相等；2000、2200、2400 ms 的动态 blur 与对应静态 blur 整幅画面相等，涵盖小、大两种装饰边缘。已查看拼图，内部硬裁剪仍清晰可见。

该单行样例的事件数：普通 28、静态 glow 42、动态 glow 798、无变化采样 532。回调目前不会自动消除相邻相同属性采样，调用方应仅在需要时启用。采样与缩放组合的全面像素对照仍待完成，不能把此次未缩放样例推广到所有动态效果。

修复后重新测量同一 120 行负载：普通/双色/四轨 union 均为 3,360 事件、980,597 bytes；四轨 priority 为 13,440 事件、4,084,697 bytes；pulse + glow 为 16,200 事件、5,282,462 bytes。生成中位数分别约 151、151、197、553、390 ms。减少了与字符装饰边界无关的分段，但具体多轨样例的事件变化取决于轨道交点，不能保证总会减少。历史基线保留，新数据位于 JSON 的 `dynamic_validation` 和 `benchmark_shared_domain`。

### 采样与缩放、淡入、位移的组合

当前工具进一步扩展为十六种变体，同样九个时刻，共 144 帧。组合样例为音节整体缩放到 1.3 倍，800 ms 淡入/淡出，40 ms 动态采样；位移变体在 x=±16、y=8 之间切换，辉光变体在 blur=3/30 之间切换。

首次运行发现无变化的采样回调也会在 1000、1200、1250、1800 ms 改变画面。原因是采样窗口成为新的曲线细分边界，改变缩放与裁剪乘积的近似线段，并再次取整透明度。修复后编译器先使用原始窗口和关键时刻细分，再截取与采样窗口重合的曝光区间；move、scale、clip、alpha、border 和 blur 的原始插值端点保留，时间改为相对当前曝光起点。

全部九个时刻通过严格逐像素对照：无变化采样与普通 pulse/fade 相等；动态位移与完整参考画面的相应平移相等；动态 blur 与该时刻相应静态 blur 的 pulse/fade 参考相等（包含半透明边缘）。已查看 1200/1800 ms 组合拼图。新数据保存在基线 JSON 的 `combined_sampling_validation`。

事件成本：普通 pulse/fade 为 238，采样后为 700；静态 pulse/fade/glow 为 357，动态 blur 组合为 1,050。保留原始细分会使一个采样区间输出多个事件，预估之后仍必须执行最终事件上限检查。新增单元测试把所有 ASS 插值时间还原为绝对时间，比较采样与未采样事件的完整标签，防止仅在选定关键帧一致。

这些结果只验证固定字体、整音节缩放、整数位移和指定函数；逐字动态错峰、ruby 跟随、亚像素路径、其他字体与复杂多轨的组合仍需单独验收。

### ruby 的两种强调策略

后续加入 `ruby_static`、`ruby_none`、`ruby_follow`、`ruby_sampled`，使用两段读音 `ka`/`raoke`，分别在 1000–1400 和 1600–2000 ms 演唱。ruby 向上偏移 30 px，使正文和 ruby 的检查区域互不重叠。整体缩放仍为 1.3 倍，淡入/淡出为 800 ms。

当前命令生成 20 种变体，在 990、1000、1200、1250、1400、1500、1600、1800、2000、2200、2400 ms 保存共 220 帧。所有检查通过：ruby 不跟随时与无缩放 ruby 参考相等；跟随策略切换不改变正文像素；采样跟随模式与未采样模式整帧相等。1500 ms 还要求跟随前后 ruby 区域存在实际差异。已查看读音交界和停顿中的三时刻拼图，ruby 的扫色在停顿期间保持，跟随模式绕正文中心缩放并改变相对距离。

`test_ruby_timing.py` 在真实布局下额外检查两段 ruby 的区域映射、曲线平台、重复保持/重置、结束保持/隐藏，逐点比较生成 mask 与正文轨道的覆盖语义。它不替代复杂文字的 shaping 验证。

事件数依次为 108、290、322、916。原始报告保存在基线 JSON 的 `ruby_validation`。此样例验证的是正文整体缩放下的两种 ruby 策略，不包含独立 ruby 逐字符强调或不同字体组合。

### 连续采样区间合并

采样求值现在合并同一原始图层上时间连续、有效几何和外观完全相同的曝光区间。所有时间点仍执行回调及上限校验，不使用浮点容差，不跨空档合并。不同颜色分区或原始图层保持独立。

最初的画面对照发现，同层事件若按开始时间排序，合并会改变 libass 的 ReadOrder，从而改变重叠辉光；已修正为按稳定来源排序。同一 ASS layer 内的来源顺序不再随曝光起点变化；显式 `order` 仍优先决定叠放层次。该修正意味着旧版本的少量重叠边缘像素可能变化，不能声称相对旧排序的所有画面均不变。

在相同的新排序下分别运行未合并版本与合并版本，220 帧逐像素相等，全部既有画面断言通过。未合并对照在独立验证进程内逐个原始采样区间求值，不修改仓库生产代码。主要事件成本如下：

| 样例 | 合并前 | 合并后 |
| --- | ---: | ---: |
| 恒等采样扫色 | 532 | 28 |
| 动态 blur | 798 | 126 |
| 恒等采样 pulse/fade | 700 | 238 |
| 分段位移 pulse/fade | 700 | 294 |
| 动态 blur 与 pulse/fade | 1,050 | 413 |
| ruby 跟随并采样 | 916 | 322 |

120 行成本工具新增恒等采样负载，事件数与普通扫色同为 3,360；生成中位数约 1,249 ms，普通扫色约 157 ms。合并降低输出事件，不消除采样回调和属性处理成本；输出 bytes 还包含采样来源标记，不能宣称与普通扫色文件完全相同。原始结果见基线 JSON 的 `sampling_coalescing`。

### 连字扩展：画面门限尚未通过

`python -m tools.render_effects /tmp/kara-ligatures --text 'office ffi'` 生成 258 个事件及三种强调模式的关键帧。候选字符现在通过逐步扩大来源范围匹配原始轮廓，将 `ffi` 保留成一个绘制单元；不会将其拆成独立的 f/f/i。

已查看 1500 ms 画面，三种模式下连字保持完整。静态整段对照的最大通道差为 31、差异像素数为 1,656；原有门限为 32/500，因此该新样例仍返回失败。没有扩大门限或将其算作通过；下一步需要定位独立定位、基线与子像素取整对新样例的具体影响。此结果不否定轮廓级来源匹配，但不足以证明最终静态排版画面验收。

后续修复：上述失败来自测量在零起点进行，而 libass 的位图量化还依赖整行首字形的子像素偏移。仅恢复原始 glyph origin 还不够，会让另一组普通文字样例退化。当前原生接口通过补丁 `003-libass-glyph-origin.patch` 保留位图量化前的字形位置，`text_shape` 另接受实际水平放置坐标；完整文本与候选单元在该起点下核对轮廓，再确定独立绘制位置。来源位置还用于确认多字形 cluster 的内部偏移没有变化。

重新构建原生扩展后，`Karaoke` 和 `office ffi` 的静态对照均为 **0 个差异像素、最大通道差 0**，原门限不变。220 帧效果回归全部通过；增加实际位置下重新测量独立单元并与整段轮廓比较的测试。原始记录保存在基线 JSON 的 `positioned_cluster_validation`。此结论限定在固定字体样例；轮廓仍经过位图变换，不能把这些数据称为未量化的完整原始字形轮廓。

### 与无裁剪参考比较装饰边缘

`validate_effects` 新增常规及斜体 `AV fj` 的粗描边/强辉光组合：正文描边 8 px、辉光 blur 30、辉光描边 12 px。参考直接从相同布局产生独立 `TextLayer`，不设置 clip；因此能够检测配方生成的裁剪边界是否截掉可见装饰。

普通扫色在 2000/2200/2400 ms 与无裁剪参考逐像素相等。另设置 100 ms 预扫和 200 ms 收尾，在 2200/2400 ms 与无裁剪参考相等；2000 ms 必须仍有可见差异，以确认收尾没有提前释放。已查看两时刻三组斜体对照，尾部裁剪在收尾后消失。普通扫色每组 24 个事件，无裁剪参考每组 8 个；更详细成本见 JSON。

当前总计 26 变体、11 时刻、286 帧，全部检查通过。固定常规和斜体字体的摘要均写入 `decoration_boundary_validation`。这些结果支持该样例的外缘完整性，不把经验边界估计推广成任意字体与参数的保证，也不证明不同轨道交界处的辉光接缝已经解决。

### 多轨辉光

新增 blur 30 的重复同色 union 和相邻区域并行扫色；priority 覆盖使用蓝色 blur 40、描边 5，与底层红色 blur 30、描边 3 不同。采样新增 1690/1700 ms，以检查 1700 ms 的精确退出。

所有时刻的重复 union 与单轨逐像素相等；priority 在 1690 ms 必须与底层不同，1700 ms 及之后必须与底层整帧相等；两个相邻区域全部完成后与完整单轨相等。已查看退出前后拼图。这验证了重复覆盖不加亮、覆盖退出恢复及同色分区完成后不残留接缝，不证明不同外观在同时扫色时的交界没有额外接缝。

当前 `validate_effects` 为 29 变体、13 时刻，共 377 帧，全部检查通过，原始记录位于 `glow_track_validation`。所有旧变体也在新增时刻重新检查。

### 变速、平台与手动区域

新增三种变体：分段主扫、同曲线 blur 30、手动划分左右半区。曲线为 `(0,0)→(0.25,0.5)→(0.5,0.5)→(1,1)`；手动区间则为左半区 1000–1250 ms、右半区 1500–2000 ms，中间保持。

对照使用解析映射：变速 1200 ms 对应线性 1400 ms，变速 1250–1500 ms 对应线性 1500 ms，后半程恢复相同时刻。全画面逐像素比较通过，强辉光与相应线性强辉光参考同样通过；手动区域与曲线表达相等。已查看停顿前和停顿期间的拼图，主体前沿在字内保持。没有把辉光面积或亮起像素面积用于定义进度。

这三组分别产生 56、84、56 个事件。当前工具总计 32 种变体、13 个时刻、416 帧，全部检查通过；原始参数及结果记录为 `speed_mapping_validation`。

## 合成歌词成本

工作负载为 120 行，每行 7 个拉丁字符、1.5 秒演唱、2.5 秒显示。每组运行两次，计时为生成阶段的中位数，包含布局和 ASS 事件编译，不包含视频渲染。这是可重复的合成歌曲负载，不是真实歌曲或其他设备的性能保证。
