# Karaoke 脚本化特效接口实施计划

目标是在现有 kara-templater 上增加面向歌词的 Python 特效接口，让调用方能够封装、组合和定制扫色、强调、入场及退场动画。库统一处理正文与 ruby 的时间映射、视觉分层和 ASS 事件展开。

首个里程碑是用统一的脚本接口解决实际应用中的歌词特效需求，替代重复的模板拼接与专用扫色实现。设计不以旧接口、旧参数或旧画面的兼容为约束；功能被更好的方案完整替代后，直接删除旧功能及其维护代码。未完成部分的类型名和模块名仍为拟议设计；TODO 完成时应同时满足对应验收条件。

## 范围与边界

- 以目标功能决定入口和数据模型；不要求保留 `apply_templates()`、旧模板语义或原函数签名。被新功能完整替代的入口直接移除，不添加兼容包装。
- 按新模型需要复用或重构歌词数据与布局能力，允许修改现有类型；不为保持旧数据结构增加重复抽象。
- 新接口直接生成 ASS 事件，无需先生成含 Python 表达式的模板字符串。
- 核心对象围绕歌词行、歌词单元、ruby、演唱进度、显示窗口和特效配方设计。
- 首版覆盖静态定位、淡入淡出、缩放强调、分段扫色、正文与 ruby 配色及辉光分层；缩放包含逐字扫到触发、所有字同时独立缩放、整个音节整体缩放三种可选模式。
- 首版支持行内按文本范围配置唱前和唱后颜色、多个区域并行扫色，以及重叠区域的显式合并、覆盖或叠加策略。
- 通用场景树、视频渲染后端、GUI、任意图形系统、自动分页排轨不纳入首版。调用方可提供排好的位置和显示窗口。
- 自定义时间函数和采样输出在核心效果模型稳定后实现；复杂辉光合成不以增加时间采样作为通用解法。

## 核心契约

### 时间与演唱进度

内部使用整数毫秒的绝对时间。显示窗口与演唱窗口独立；ASS 事件内部的相对时间只在输出阶段计算。

`HighlightTrack` 描述时间到演唱进度的映射，空间映射再将进度映射到正文或 ruby 区域。停顿必须保持进度不变。重复演唱同一区域与依次唱过不同区域必须显式区分。

### 几何与外观

区分 `layout_bounds`、`ink_bounds` 和 `paint_bounds`，分别表示排版范围、字形墨迹范围和包含装饰的范围。首版可以使用排版范围加显式补偿，但必须标记其近似性质；完整 ink bounds 需要后续扩展测量能力。

外观包含唱前、唱后填色、描边和辉光。用户操作一个歌词对象，内部展开成多个 ASS 事件。位置、缩放、透明度与显示窗口应同步应用到需要跟随的视觉层。

### 扫色计时区间与装饰过渡

动态添加的描边、blur 等效果会扩大实际绘制范围，但扩大后的范围不应直接成为演唱进度的分母。即使完整测量了特效范围，若将扫色时间均匀分配给整个范围，仍可能花大量时间穿过模糊区域，使文字主体的视觉进度偏离演唱进度。

增加独立的 `timing_region`，表示扫色计时区间。默认策略参考文字主体的几何范围；首版可使用明确标记的布局近似，并允许用户指定边界或偏移。它不必等于 `layout_bounds`、`ink_bounds` 或 `paint_bounds` 中的任意一个。`paint_bounds` 用于确定装饰需要覆盖到哪里，`timing_region` 和进度曲线决定何时扫到文字主体的哪个位置。

| 阶段 | 空间范围 | 时间策略 |
| --- | --- | --- |
| 预扫 | 装饰左边缘到计时起点 | 可提前开始或快速完成，独立配置 `lead_ms` |
| 主扫 | 计时起点到计时终点 | 使用 segment 演唱时间和主体进度曲线，保留停顿与分段映射 |
| 收尾 | 计时终点到装饰右边缘 | 可延后结束或快速释放，独立配置 `tail_ms` |

以上描述以从左到右扫色为例。空间补偿 `padding_px` 与时间补偿独立；调整 blur 或装饰范围时，不自动改变主体在同一演唱时刻的位置。主扫曲线是可配置的视觉节奏策略。原有两阶段变速和 `clip_size` 只用于理解视觉问题；新接口以计时区间、进度曲线和装饰过渡替代它们，不保留旧参数耦合或专用兼容模式。

当前配置将显式计时区域放在 `SingingPass(region=..., curve=...)`；使用默认轨道时通过 `Sweep(progress_curve=..., edges=EdgeSweep(padding_px=..., lead_ms=..., tail_ms=...))` 配置共享曲线。显式轨道自己拥有曲线，不能再同时传入非默认 `Sweep.progress_curve`。库先计算主体演唱进度，再计算各视觉层的装饰过渡。逐字强调只跟随主体进度，不由辉光的预扫触发；多条轨道可共享主体时间与空间映射，同时拥有不同的装饰范围。

动态装饰范围可以影响裁剪安全边界，但不能反向修改主体计时。预扫和收尾超出显示窗口时沿用窗口策略；相邻 segment 或并行轨道的装饰过渡发生重叠时，沿用已选区域合成规则，不能把外扩范围当成新的已唱文字区域。

验收以主体进度稳定、边缘过渡可控和实际画面合理为准，不要求亮起像素面积占比等于演唱时间占比。字形与辉光分布并不均匀，需要用代表性字体和效果参数进行视觉校准。

### 行内配色与并行扫色

配色范围与演唱分段独立。例如「今天」可以共用一个演唱时间段，但「今」唱后变红、「天」唱后变蓝，不需要为颜色变化拆分时间段。文本范围使用稳定的来源引用，与可绘制单元建立映射；颜色边界不能破坏已有排版或强制拆开不可独立绘制的字形。

一行持有多条独立 `HighlightTrack`，每条具有稳定标识、目标范围、时间映射和可选的唱后外观覆盖。每条轨道可以独立开始、停顿、完成或重复；整行状态是各轨道作用区域的集合，不能压成一个进度值或单一连续扫色前沿。

外观按行默认值、文本范围覆盖、轨道唱后覆盖的顺序解析。文本范围覆盖之间发生冲突时须指定优先级，否则报错；ruby 配色可显式配置或按关联正文继承，跨多个正文颜色范围时必须明确映射。

| 重叠策略 | 适用情况 | 语义 |
| --- | --- | --- |
| 合并已唱区域 | 各轨道使用相同外观 | 取各轨道已唱区域的并集，覆盖处只绘制一次，避免重复增强透明度和辉光 |
| 按优先级覆盖 | 各轨道使用不同颜色 | 在重叠的已唱区域选取优先级最高的轨道外观；优先级相同且冲突时报错 |
| 独立图层叠加 | 有意制作多重扫光 | 基础未唱层共享，各轨道高亮层按明确层序与透明度叠加，保留叠加导致的亮度变化 |

不同区域的轨道独立运行。区域重叠时必须选择组合策略；不能依赖输入列表顺序或 ASS 事件的偶然顺序。轨道演唱结束后的保持、隐藏或重置决定其何时不再参与合成；高优先级轨道退出后，仍有效的低优先级轨道重新显露。

合并与覆盖是视觉区域的语义，不保证任意装饰都能由一组矩形标签精确表达。首版实现受支持的区域与外观组合，并验证裁剪接缝及辉光边界；无法保持所选语义时明确诊断，不静默退化成独立叠加。

### 强调动画的触发与作用范围

触发时机、作用范围和缩放中心独立配置。`syl / char` 只表示对象范围，不能同时隐含触发规则和变换中心。

| 模式 | 触发时机 | 作用范围 | 缩放中心 |
| --- | --- | --- | --- |
| 扫到哪个字就缩放哪个字 | 高亮前沿进入该字区域 | 当前被触发的字 | 该字中心 |
| 所有字同时独立缩放 | 音节开始 | 音节内全部字 | 每个字各自的中心，字中心位置保持不变 |
| 整个音节整体缩放 | 音节开始 | 音节整体 | 音节中心，字形与字间位置共同变化 |

当前接口如下：

```python
# 扫到哪个字就触发哪个字
Pulse(trigger=HighlightEnter(threshold="enter"),
      target="triggering_char", pivot="char_center", scale=1.1)

# 同时触发所有字，各自围绕中心缩放
Pulse(trigger=SyllableStart(),
      target="chars", pivot="each_center", scale=1.1)

# 围绕音节中心整体缩放
Pulse(trigger=SyllableStart(),
      target="syllable", pivot="group_center", scale=1.1)
```

音节开始与 segment 开始是不同锚点。一个音节包含多个 segment 时，前者默认取最早演唱起点，后者按所选 segment 分别触发；静态文本没有隐式演唱触发。

逐字触发时间从高亮轨道的主体进度与未施加强调变换的逐字计时区间计算，不按字符数平分音节时长，也不让缩放后的边界反过来改变触发时间。支持进入、到达中心和完成三种阈值；变速、停顿与 ruby 映射均沿用高亮轨道语义。装饰边缘的提前补偿不触发演唱强调。

动画时长另行指定，可使用固定毫秒或该字被扫过的时间。重复演唱是否重新触发需要显式配置；再次触发时若前一次动画尚未结束，沿用属性冲突检查，不默默覆盖。零时长跨越多个阈值时，按所选触发类型每次演唱最多触发一次；空白或无可绘制区域的单元默认不触发视觉强调。

多轨情况下，强调触发器须选择指定轨道、任意轨道首次到达或各轨道分别到达。首次到达按目标、触发类型和显式演唱轮次去重，同时到达只产生一次触发；各轨道分别触发仍执行动画冲突检查。触发默认依据轨道自身进度，不因视觉上被更高优先级轨道覆盖而失效。

逐字绘制应保留原始排版位置。首版必须定义可独立绘制的文字单元，不能把 Unicode 码点直接当成可拆开的字形；组合字符保持完整，对无法安全拆开的 shaping cluster 给出明确诊断。完整测量扩展可以后续推进，三种模式在首版支持的文字范围内都必须可用。

### 效果计划与输出

拟议流程为：

```text
结构化歌词或 ASS 输入
        ↓
歌词布局与显示窗口
        ↓
高亮轨道、外观与动画组成的效果计划
        ↓
ASS 事件生成器
        ↓
Document
```

效果计划只表达 karaoke 所需信息。公开接口允许函数或带 `build()` 方法的对象创建计划，不建立深层继承体系。底层保留直接提供 `Line` 的出口，并明确它不参与自动属性合成。

- `animation.py`：三类触发器、三种 `Pulse` 配置、逐字阈值求解、首次/逐轨/指定轨道选择、轮次去重、缩放冲突及窗口处理。`point_at()` 可验证整体缩放时字间位置变化。首版曲线及 pulse 起落均为分段线性。
- `composition.py`：RGB `Color`、`Paint`、`Glow` 和已唱区域的三种合成语义。相同区域合并只保留一份外观，优先级冲突报错，独立叠加需要明确层序。这是目标画面模型，尚不代表 ASS 能精确输出每种辉光组合。
- `examples/timeline.py`：运行 `python -m examples.timeline`，查看三种缩放、装饰边界变化以及双轨覆盖退出的结果；当前不生成 ASS。
- `tests/test_timeline.py`、`tests/test_animation.py`、`tests/test_composition.py`：覆盖上述语义。pytest 限定收集 `tests/`，避免引入 `refs/` 项目的测试及依赖。

当前契约细节：

- 时间输入为非负整数毫秒，显示窗口必须有正长度；求值和触发时刻保留浮点精度，ASS 时间量化留到生成阶段。
- 分段曲线允许进度平台表示停顿；反向进度和重复时间节点报错。零时长演唱使用 `SingingPass(start_ms=end_ms)`。
- 同一轨道的分区不能时间重叠，同轮次不能重复覆盖同一区域；并行演唱使用独立轨道，重复演唱显式增加 `round_id`。`repeat="reset"` 在下一轮开始时清除之前轮次，`end_behavior="hide"` 在最后一个演唱区间结束时退出。
- 相邻分区共用边界时，字符进入归属于后一区间，字符完成归属于前一区间；二者之间的停顿不能被跳过。阈值在映射外时不触发；缺少完整遍历边界时，使用遍历时长会报错，调用方须明确指定固定时长。
- `layout_characters()` 现可提供经过轮廓验证的 `DrawableCharacter`，其 `.target` 可直接用于强调计划。支持范围及诊断见后续进度。
- 缩放按给定时长先线性放大再线性回落。零时长遍历产生一次零长度触发，不生成可见缩放；需要可见强调时显式指定 `duration_ms`。
- 窗口截断保留原动画时刻并报告诊断，避免动画从显示窗口重新开始。主体计时不读取外观或装饰范围。

接续实现顺序：建立固定环境画面样例；实现 ASS 生成器及统一入口；完成替代后删除旧模板和专用扫色实现。当前保留旧实现是因为输出能力尚未被替代，不新增任何兼容包装。


### 字符布局与配色范围实现
