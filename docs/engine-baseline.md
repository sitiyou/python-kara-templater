# 固定环境、质量与成本基线

本页汇总案例卡预先指定的配置和当前已测输出，不改变预算或质量门槛。第 102 批重新编译十二例及整曲，逐份保存后核对 SHA-256：全部与已有四背景、整曲独立片段和整曲报告一致；字体字节也一致。核对结果见 [baseline-current-audit.json](baseline-current-audit.json)。此次只重新生成和比对文件，没有重复播放测量。

## 可复现环境

| 项目 | 固定值或记录位置 |
| --- | --- |
| 脚本分辨率 | 1280×720 |
| 输出采样 | 默认 50 Hz，中点保持；原生事件按各自标签时钟；ASS 厘秒量化 |
| 四背景播放检查 | 每例 6 秒、100 Hz、600 帧；整数毫秒时间基，查询 `10*N+1` ms；置换顺序 `(N*137)%600` |
| 整曲播放检查 | 180 秒、50 Hz、9000 帧，`20*N+1` ms；150 次新实例逆序跳转 |
| 背景 | 自制黑、白、棋盘、RGB 渐变；每份报告保存 PNG 哈希，RGB24 输入/输出 |
| 字体 | 仓库 DejaVuSans.ttf 与 KaraTestCJK.ttf；报告记录 family 和 SHA-256，验证器向渲染器提供实际文件 |
| libass | `0.17.5-0-g4a05d8127f525943ebf45fdc6497c9e665947f0d` |
| 塑形 | FriBidi 1.0.16、HarfBuzz-ng 15.1.0 |
| 耗时测量宿主 | Linux 7.3.1-1-cachyos、x86_64、glibc 2.44、16 个逻辑 CPU；见整曲报告 |

渲染版本来自真实 FFmpeg 日志。内存/耗时属于这台机器和该次进程测量，不是通用实时播放承诺。子进程 ru_maxrss 可能包含 exec 前继承的内存，不解释为独立稳定态 FFmpeg 内存。

`+1 ms` 避免 FFmpeg 浮点时间边界截断；它不能替代精确边界测试。起止、断点及全部静态输出区间的独立检查分别列在逐例验收文档。相同字体名称不保证播放器选中相同字节；实际播放需提供指定字体。

## 质量和资源预算

案例卡在输出前固定：几何 1 px 容差、颜色通道目标 2/255、时间量化不超过 10 ms；光栅边缘误差单列，任意连续函数不凭帧率获得误差界。逐例的几何/合成参考、覆盖范围与剩余限制见 [全案例索引](case-interface-audit.md)。例如 E08 快速笔尖相对连续理想轨迹的已观察误差约 3.312 px，与其声明采样目标的几何容差分别报告。

普通单例上限为 25,000 记录、1,000 峰值活动事件、10 MiB；整曲上限为 250,000、2,000、100 MiB。路径点上限 4,096，颜色条带上限 1,024，布尔工作量 1,000,000。报告事件数是可见生成 Dialogue，预检还计入必要归属记录；字节和最终活动峰值包括保留内容。

[整曲报告](whole-song-validation.json)记录生成约 4.64 秒、9000 帧连续渲染约 15.39 秒、150 次跳转一致、重复片段 5400 帧和独立案例 3600 帧一致。单例的生成/播放耗时见对应 `scene-*-validation.json`；四背景报告的 seconds 包含该工具的整例检查工作，不与纯渲染耗时混用。独立参考可故意展开更多条带以提供证据，产品预算衡量实际导出，不把参考实现的事件数当作用户输出目标。

## 重现与历史数据

```sh
uv run python -m tools.validate_engine_assets build/engine-assets.json
uv run python -m tools.validate_engine_backgrounds --case E11 build/sweep-backgrounds
uv run python -m tools.validate_whole_song build/whole-song-current
```

其他案例替换 `--case`；完整四背景命令省略该参数。每个当前报告的路径、背景/字体哈希、渲染器版本与 ASS 哈希集中在本轮核对 JSON。旧 `before-*` 报告和案例卡早期表格保留用于解释视觉变化，不能替代当前输出证据。单独的栅格/覆盖率实验使用显式较大预算，不混入十二例基线。

本基线覆盖 libass；其他播放器和最终发行包仍需另行验收。
