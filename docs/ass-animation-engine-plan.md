# 标准 ASS 动画引擎计划

状态：首版计划已完成。逐项证据及验证边界见 [验收索引](ass-animation-engine-acceptance.md)，实施历史见 [进度记录](ass-animation-engine-progress.md) 和 [案例卡](ass-animation-engine-cases.md)，执行清单见 [TODO](ass-animation-engine-todo.md)。固定视觉基线为 libass；Windows ABI 发行包在 Wine 内验证，不等同真实 Windows 宿主或全部播放器逐像素验收。本文保留设计形成时的候选方案与阶段条件，当前公共接口以 scenes.md 和能力清单为准。

## 目标与约束

构建以歌词时间轴为基础、具有类似 Manim 的对象组合和动画编排能力、最终只输出标准 ASS 的 Python 特效引擎。`examples/layered_glow.py` 是代表性用例之一；公共接口须同时接受下文不同机制的效果检验。

- 输出使用标准 ASS 事件、样式、标签和矢量绘图，播放端无需自定义插件或修改后的渲染器。生成阶段可使用原生库进行测量、几何计算和采样。
- 自定义效果能够创建对象、定义几何与属性、安排时间和组合行为；常用预设通过同一扩展接口实现。
- 所有公开构造参数、选择结果、上下文、回调和返回值都有明确类型，不泄漏 `Any` 或 `Unknown`；代码通过 Ruff、ty 和相关测试。
- 保留原始歌词、演唱片段、注音和来源信息。视觉拆分、动画提前或延后不隐式修改原始演唱时间。
- 输出质量、误差、文件大小和播放成本共同构成验收标准。昂贵的表达方式必须显式选择并受预算限制。
- 本计划建立新方向的验收依据；历史计划中的完成标记不等于本计划已经完成。实施时保留现有工作树修改，逐项评估可复用模块。

## 统一 Document 与旧模板兼容

已确认的公共边界为 Document → 应用模板或特效 → 标准 ASS 输出。Document 可以由 ASS 解析，也可以直接用 Python 构造或修改；两种来源必须具有相同语义。

文件入口的流程为：输入 ASS → 解析 Document → 特效框架（旧模板兼容前端或新效果前端）→ 标准 ASS 文档 → 保存 ASS。解析与保存是入口适配，框架不依赖输入文件路径。内部场景计划服务于编译，不替代公共 Document 输入。

Document 保留脚本信息、样式、事件、原始顺序、注释、模板/code 行及来源，并提供类型化的文本片段、时间与扩展元数据。区分忠实解析和效果绑定：解析不得只提取 k 时间后丢弃其余标签；未处理的普通字幕和元数据按明确规则保留。无法解释的标签要保留原文，并在需要对其应用效果时报告能力限制。

标准颜色标签（如 `\1c`、`\3c`）和样式重置应解析为有作用范围的文本属性，并明确与行样式、Python 配置及动画的优先级。可用标准标签表达的逐字颜色优先沿用标准语义；导唱锚点等新增语义使用本库命名空间标记。扩展标记解析为结构化数据，由框架消费并生成标准 ASS。

旧功能兼容以 git 标签 v0.1.0 为基准：模板行、code 行、$variables、modifiers、helper functions，以及 !…! 内的 Python 表达式。该版本没有 Lua 兼容解释器，因此本计划的旧版本兼容不扩大为任意 Lua 模板兼容。旧模板执行是显式选择的兼容前端；单纯解析 Document 和导唱标记不执行代码。

兼容前端复用旧模板的执行语义并接入统一输出流程。能够结构化的结果进入场景计划；旧模板直接生成的标准 ASS 事件可通过类型化事件节点保留，避免强制反解造成语义变化。两类结果共享输出顺序、来源、预算和序列化规则。新旧效果混用时明确目标归属、执行顺序及重复生成规则，不对生成结果再次隐式应用模板。

兼容验收包括文件入口与直接 Document 入口等价、旧示例和模板行为回归、颜色与重置标签作用域、未匹配事件保留、重复应用和源模板保存。已有旧功能作为持续回归约束，从 P0 建立基线，P2 接入最小兼容路径，P5 完成兼容矩阵。

首版已核对的功能范围、昂贵出口、明确限制及当前降级策略见 [能力清单](ass-engine-capabilities.md)。清单不替代各阶段退出条件，也不取消原定案例的视觉验收。

以下是职责划分，类名与方法签名在原型阶段确定。

### 歌词与时间

歌词模型提供行、演唱单元、片段、文本范围、注音和元数据。词分组允许用户指定或提供分词策略；字符选择明确区分 Unicode 文本范围与可独立绘制的塑形簇。

时间锚点涵盖整曲绝对时间、显示窗口、演唱开始与结束、片段和前后单元。明确局部时间、时长缩放、提前入场与延后收尾；选择一种统一的公开时间单位，并定义旧毫秒接口适配方式。

### 视觉对象与几何

文字、路径和组具有独立身份、寿命、坐标、锚点、层次及来源。一个歌词来源可以生成多个视觉对象，装饰对象也可独立存在。组变换只组合一次，引用和跟随关系必须检测依赖环。

几何能力分阶段覆盖文字测量、字形轮廓、基本图形、路径采样、路径布局、切片与遮罩，随后增加布尔操作、路径显露和形状插值。布局范围、字形墨迹范围与描边模糊后的绘制范围分别定义。

### 属性与动画

统一表达位置、横纵缩放、旋转、倾斜、变换中心、颜色、透明度、描边、阴影和模糊。每种对象明确支持的属性及其值域，使用类型化协议或值对象扩展，避免无类型属性字典和字符串路径成为公共扩展契约。

动画支持顺序、并行、错峰、重复、关键帧、缓动和自定义时间函数。明确同属性冲突、接管、叠加、结束后保持或释放的规则。编排和求值分离；任意时刻采样不依赖此前访问过哪些时刻。

### 对象生成与关系

粒子、残影、碎片和装饰以对象生成及动画组合实现。定义生成时刻、初始状态、寿命、图层、来源及稳定随机种子。随机性绑定对象身份和时间，不能随采样顺序改变。需要状态推进的模拟在固定时间步预计算并缓存，再供场景求值。

跟随可引用当前几何，残影可引用过去状态；区分出生时捕获位置与持续跟随发射源。明确父组结束后子对象的可见性及寿命。

### 标准 ASS 编译

| 表达类别 | 策略与验收 |
| --- | --- |
| 原生表达 | 优先使用文本、绘图、`\move`、`\t`、淡入淡出及可动画矩形裁剪；验证时间与变换语义 |
| 事件展开 | 曲线、复杂缓动、动态矢量遮罩和变形分段或采样为事件；报告时间与空间近似 |
| 昂贵近似 | 空间分条、像素矩形等显式开启，执行事件、输出体积、路径复杂度和采样预算 |
| 无可接受表达 | 给出来源、对象、时间、原因和可选替代方案；不静默改变语义 |

标准 `\move` 是匀速直线运动，矢量裁剪无法通过 `\t` 动画，参见 [ASS 标签文档](https://aegisub.org/docs/latest/ass_tags/)。组透明度、模糊与裁剪的执行顺序、混合模式不能直接套用通用图形引擎的语义。

连续函数的采样误差与渲染器差异分别报告。任意回调不能仅凭采样频率声称有严格误差上界。合并相邻等价事件、复用样式等优化必须保持既定语义。

兼容性先建立 libass 的可复现基线，并记录 VSFilter 系列标准标签的差异与验证环境；不得用非标准扩展标签完成标准 ASS 验收。预览必须使用实际导出的 ASS。

## 验收方法

- 先用短片段定位问题，再以多行歌词和整曲压力夹具验证累计成本。
- 关键帧涵盖入场、唱前、演唱中间、结束、收尾和相邻动画重叠；使用黑白背景及代表性视频背景。
- 同时检查连续播放和跳转；不能只检查端点快照。
- 保留预期参考、实际输出、差异说明、字体及渲染环境、随机种子、事件数、峰值活动事件数、文件体积、生成和渲染耗时。
- 测试组合行为：旋转与遮罩、缩放与注音、渐变与残影、组变换与局部动画、短音节、零时长、连字、空格与字体回退。
- P0 根据指定分辨率、帧率、字体和机器测量确定预算；在生成结果之前设定，不因结果超限而自动放宽。
- 相关单元测试、集成测试、视觉验证，以及 `uv run ruff check .`、`uv run ty check` 全部通过后才完成对应实现阶段。

## 复用与迁移

优先审计并复用现有 ASS 解析与输出、原生文本测量、来源映射、歌词时序、采样和动画编排。参考 `refs/textual` 的公开类型设计，但对象模型由效果需求决定。

`Track` 作为歌词效果的便捷配置入口，逐步转换为同一场景计划。新旧入口共享后端能力和预算诊断。旧示例的兼容范围、视觉变化和弃用安排在迁移表中记录，避免长期维护多套相互独立的执行语义。

已有[后端审计](track-backend-audit.md)与[动画时间轴](animation-timelines.md)作为审计输入；已有栅格方案须重新评估适用范围与成本。


## 扫色交界与樱花效果的补充契约

E11 来自用户提供的两张文字扫色截图。静态图片用于表达视觉目标，不能证明原作使用的渲染器、标签或时间曲线。验收须分别定义填充的颜色过渡宽度、描边是否过渡、辉光是否跨越前沿扩散，以及基础与高亮外观的透明度。

标准 ASS 没有直接的羽化裁剪标签。多条窄裁剪区域与插值颜色可近似柔和交界，但多层透明叠加不能自动等价于颜色插值。普通 blur 作用于文字绘制并不自动柔化裁剪边界；区域着色后再模糊的语义需要专门的近似策略。P3 比较分条、图层和显式栅格方案，记录缝隙、色差及输出成本，再决定默认策略。

E04 增加樱花飘散变体：花瓣使用矢量路径，具有位置、漂移、旋转、缩放、透明度和寿命；支持独立场景发射及由音节或扫色前沿触发。曲线和摆动由生成阶段计算并输出标准 ASS 事件。花瓣不必每个都逐帧展开；可原生表达的区间优先使用标签。验证花瓣峰值活动数量、模糊面积和叠加成本。

## 导唱符与输入标记

导唱符是一种可生成的视觉组件，具有独立内容、时间和布局策略。支持圆点、数字、文字、逐级短条和用户提供的图形组合；提供用户自定义构建接口，生成普通视觉对象和动画。

- 行内模式参与歌词前的排版、间距、对齐和占位，并定义消失后保留占位或重新排版的规则。
- 独立模式支持画面坐标和相对歌词锚点，不占正文宽度；明确是否跟随歌词变换。
- 支持按首音节、指定音节或绝对时间触发，用户指定提前量、持续时间、各步时点和消失方式。无节拍输入时不得假定每个音节等于一拍。
- 同一歌词可绑定多个导唱对象；导唱对象不改变歌词文本、演唱游标和注音归属。
- 代码直接构造和输入文件标记映射到同一类型化模型。输入标记仅承担锚点、预设标识和已声明参数，样式与生成逻辑由 Python 提供。

自定义标记属于本库的输入协议，编译后输出标准 ASS。P1 已比较有命名空间的注释块、独立 Comment 事件和自定义覆盖标签，当前 v1 采用 `{kara:v1 cue id=... preset=... placement=...}` 注释标记；其参数、引用规则、作用域和保存往返契约见 scenes.md 的“输入标记载体与 v1 契约”。

标记解析须定义作用域、锚点绑定、参数类型、重复标记、未知预设和错误来源定位；扩展标记解析不执行 Python/Lua；旧版 Python 模板的执行由显式兼容前端负责。当前 parse_karaoke 会拒绝未知反斜杠覆盖标签，因此新增协议必须显式解析并保留结构化元数据，不能依赖渲染器忽略未知标签。保留源标记时使用不会影响播放的注释记录，生成的 Dialogue 不依赖自定义标签。
